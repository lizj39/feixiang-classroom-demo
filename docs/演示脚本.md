# 5 分钟演示脚本

> 目标：让面试官在 5 分钟内看到「选择可解释 + 结果可验证 + 故障可定位」三件事，
> 而不是看完所有功能。

## 0. 准备（演示前做完，不占时间）

```bash
npm ci
npm run dev
```

浏览器打开 `http://localhost:5173`，把窗口调到 ≥1200px 宽（三栏布局）。

**开演前检查**：左栏能看到「理解方式」和「故障演示」两块按钮；右栏能看到四块证据。

## 时间轴

### 0:00–0:30 开场（30 秒）

> 「老师一句话进来，系统要自己判断用哪个教学 Skill、怎么组合，
> 然后生成一个能操作的课件 —— 而且要对『为什么这么选』和『生成得对不对』给出证据。
> 我先把最核心的一句跑给你看。」

### 0:30–1:40 组合场景 + 拖动（70 秒）

1. 点 **S2 组合 Skill** → 点「生成课件」
2. 指中间：「**一条一次函数图像 + 一个滑块**，拖动它 —— 直线按公式实时重算。」
3. 拖到大一点、再拖到 0（变成水平线）
4. 指右栏「**选择理由**」：
   > 「两个 Skill 得分 1.00 和 0.60，各自达标且槽位不冲突，所以组合。」
5. 指右栏「**验证报告**」：
   > 「四层全绿。L1 是路由选对了，L2 是 IR 里真有滑块且绑定能解析，
   > L3 是 DOM 里真有 `input[type=range]`，L4 是**真的派发事件拖了一次**、
   > 比对拖动后的路径与用新参数算出来的路径是否一致。」

### 1:40–2:20 单 Skill 与打分明细（40 秒）

1. 点 **S1** → 生成
2. 指得分表：
   > 「只有画图能力达标，0.90 分。三条证据：图像 +50、画 +20、y= +20。
   > 其余三个 Skill 是 0.00，但**也在表里** —— 不然『为什么没选它』没法回答。」
3. 指中间的提示语：
   > 「注意这里没有滑块，所以提示语不能说『拖动滑块』。文案和产物必须一致。」

### 2:20–3:20 冲突与拒答（60 秒）

1. 点 **S3** → 生成
   > 「两个练习类 Skill 抢同一个题位，都是 1.00 分，优先级也一样 —— **平局**。
   > 系统不猜，降级成两个澄清问题。」
2. 点 **S4** → 生成
   > 「班会这个需求，四个 Skill 全是 0 分，一个都不选，也不硬凑一个课件。
   > **敢说不生成**是这套东西的一部分。」

### 3:20–4:40 故障定位（80 秒，最重要）

> 「题面问：日志显示互动 Skill 已调用，但课件里没有滑块，你怎么发现和定位。
> 我先说结论：**这不是一种故障，是三种**，各自停在不同层。」

1. 点「故障演示」→ **drop-node** → 点 S2 生成
   > 「课件没有滑块。报告红在 **L1**：期望 `{function-plot, interactive-slider}`、实际只有 `{function-plot}`。
   > L2 四条全是 `skipped`。**决策与产物不一致，问题在编排。**」
2. 点 **break-binding** → 生成
   > 「这次滑块在、图也在，拖着好像还有反应。报告红在 **L2**：`bindTo.nodeId` 指向了不存在的节点。
   > 注意 **L1 是绿的** —— 这种故障肉眼基本发现不了。」
3. 点 **unregistered-renderer** → 生成
   > 「滑块位置变成一个红框占位符。报告红在 **L3**：IR 里有滑块，DOM 里没有。
   > 而**服务端那半份报告是全绿的** —— 这就是为什么 L3/L4 必须在浏览器跑。」
4. 点「正常」→ 生成 → 恢复四层全绿

### 4:40–5:00 收尾（20 秒）

> 「三个故障对应三个不同的停点，定位就变成一件查表的事：
> 先看红在哪层，再看那一层的 trace 输入输出。
> 代码、规格、故障脚本都在仓库里，`npm ci && npm run verify` 一条命令跑 275 个测试。」

## 可能被追问（一句话回答）

| 追问 | 回答 |
|---|---|
| 「打分为什么是这几个数？」 | 整数百分制：primary 50 / synonym 20 / intent 10，封顶 100。用整数是因为 `0.5+0.1≠0.6`，而阈值刚好压在 0.60 上。 |
| 「为什么不让 LLM 直接决定？」 | 那样分数不可复现、trace 无法断言、四层验证失去意义。模型做「这句话要什么」，规则做「给多少分、够不够、要不要拒」。 |
| 「LLM 挂了怎么办？」 | 降级到规则版，`degraded.reason` 写进 trace，界面显示「这次没有模型参与」。不配 key 也能完整演示。 |
| 「冲突为什么是平局就拒答？」 | 猜错的代价是老师拿到不想要的东西；问一句的代价只是多一句。 |
| 「你说的『结果可验证』和普通测试有什么区别？」 | 普通测试验函数；这里验产物：IR 里有节点、DOM 里有控件、拖动后路径与公式一致。日志说调用了不算数。 |
| 「这个 Demo 的边界在哪？」 | 见 README 的 Non-goals：不做账号/数据库/LMS，练习题是模板内容，滑块固定绑 k。 |
| 「如果要接真实题库 / 真实课件格式？」 | Skill manifest 里加 `produces` 类型与渲染器即可，路由与验证不用改 —— 这是分层带来的。 |

## 三条别做

1. **别现场改代码**。要改就切到准备好的分支，否则一个手抖毁掉整场。
2. **别超过 30 秒讲一个实现细节**。面试官要的是判断力，不是源码导览。
3. **别把每个功能都演一遍**。四个场景演两个、故障演三个，剩下的用一句话带过。
