# 故障排查指南

> 排查 `interactive-slider` 相关问题时最常见的现象：**日志显示 Skill 已调用，页面上却没有滑块。**
> 结论先说：这不是一种故障，而是三种，各自停在不同层。

## 0. 前置

```bash
npm run dev        # http://localhost:5173
```

页面布局：

- 左栏上方：示例场景（S1–S4）；左栏下方：故障演练（正常 / 三种注入）
- 中间：课件
- 右栏从上到下：理解结果 → 选择理由 → 执行链路（trace）→ **验证报告（L1–L4）** → 已注册的 Skill
- 顶栏右上角有验证徽标：`✓ 四层验证通过` / `✗ L2 失败`，不滚动就能看结论

## 1. 基线：先确认正常时是绿的

点 **S2 组合 Skill** → 生成。

- 中间：`y = 2x + 1` 的直线 + 一个可拖动的滑块
- 右栏：**✓ 四层验证全部通过**，10 条检查全绿

后面每一步都对比这个基线。

---

## 2. 现象一：课件里没有滑块

在左栏「故障演练」里点 **drop-node**（顶部出现黄色提示条），再点 S2 生成。

- 中间：只有图像，没有滑块
- 执行链路（trace）里 router 明明写着 `selected: [function-plot, interactive-slider]`

**报告停在哪：** `L1` —— `L1.route.selected-match` 失败，
期望 `{function-plot, interactive-slider}`、实际 `{function-plot}`；L2 四条全是 `skipped`。

**结论：** 决策说用了两个 Skill，产物里只有一个 → 问题在**编排**，不在渲染。

**为什么能自动发现：** L1 这条断言本身就在比对「决策」与「产物」，所以它必然先红，
不需要人肉核对日志。

---

## 3. 现象二：滑块在，但拖了没反应

点 **break-binding**，再生成。

- 中间：图像和滑块都在，拖动时数字也变
- **报告停在哪：** `L2` —— `L2.ir.slider-bound` 失败，证据指向 `page.children[2].bindTo.nodeId`，
  实际值是 `function-plot:plot-1#bug`
- **注意 L1 是绿的**：两个来源都在，决策与产物一致

**结论：** 结构合法但引用断了 → 问题在**编排的绑定**，不在节点有无。
这种故障肉眼很难发现，只有校验能抓。

---

## 4. 现象三：服务端全对，页面却没有滑块

点 **unregistered-renderer**，再生成。

- 中间：滑块位置是一个红框占位符 `⚠ 未注册的节点类型：slider`
- **报告停在哪：** `L3` —— `L3.dom.range-present` 失败，期望 1、实际 0
- **服务端返回的那半份报告 L1/L2 全是绿的**

**结论：** IR 有滑块、DOM 没有 → 问题在**渲染注册表**。

**关键点：** 如果只在服务端做验证，这条故障永远发现不了。L3/L4 必须在浏览器跑，
这不是实现偷懒，而是分工的必然 —— 它们的输入（DOM 与拖动行为）只存在于浏览器。

---

## 5. 恢复与回归

点回「正常」，重新生成 → 四层全绿。

三个注入开关对应三处真实代码位置：

| 现象 | 真实出错位置 | 拦住它的回归测试 |
|---|---|---|
| 课件缺节点 | `composer/compose.ts` 不应丢弃已选 Skill 的节点 | `tests/verify/fault-demo.test.ts`「没有故障时全绿」 |
| 绑定悬空 | 绑定必须在本次合并结果里可解析 | 同上 + `tests/ir/validate.test.ts` 的 `binding-resolves` |
| 渲染器缺项 | `render/registry.tsx` 必须覆盖全部节点类型 | `tests/web/courseware.test.tsx`「注册表覆盖 IR 全类型」 |

最后那条覆盖率断言是真正的守门员：**新增节点类型忘了注册渲染器，测试立刻红。**

## 6. 排查方法总结

这套验证的价值不在于「发现了 bug」，而在于**把定位变成一次查表**：

1. 先看报告红在哪一层 —— 那一层就是故障所在
2. 再看 trace 里那一层的输入输出 —— 就知道是哪段代码的问题
3. 三种故障对应三个停点，不需要靠猜

补充：`?bug=` 也可以直接写在地址栏（`http://localhost:5173/?bug=drop-node`），刷新后生效。
